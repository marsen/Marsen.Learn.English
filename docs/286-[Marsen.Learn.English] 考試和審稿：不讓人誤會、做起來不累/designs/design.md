# Design: 考試和審稿：不讓人誤會、做起來不累

**來源**：issue #286 的驗收條件 AC-1～14，加上商業主管補的 AC-15～19（判級 `build`：寫 design、不寫 spec）。接在 `feat/285-safe-exam` 後面。

時限 180 分鐘，估計做不完全部。順序：AC-5 → AC-1/2 → AC-4 → AC-6/8 → AC-7 → AC-3 → AC-9 →（實機檢查 AC-13/14）→ 有剩才做 AC-10 → AC-12 → AC-11。沒做的寫在最後「不做」。

## 決定紀錄（AC-18）

| 要決定 | 選了 | 為什麼 |
| --- | --- | --- |
| 完整考卷的代號（`s1-…` 開頭的 setId） | **只改畫面** | setId 是主鍵，音檔的 key、作答紀錄、審稿紀錄都綁著它；改資料要搬資料、改音檔位置。學生畫面本來就不露代號，老師／管理員畫面在代號旁加「完整考卷」標籤，不再讓人以為是 Section 1。產生端（Question.Generator）要不要換代號規則，另開工作項由骨架處理，這張不改出題工具 |
| AI 審稿意見的位置編號（`t10` 對 `s1-t10`） | **只改畫面** | 已上傳的題組資料不動。網站端依意見所屬的 Section 把 `t10` 轉成 `s{n}-t10` 查時間，顯示成和逐字稿一樣的寫法。產生端改成直接寫 `s1-t10`，另開 Question.Generator 工作項 |
| 狀態圖示的「考得到／考不到」 | 圖示只講審稿狀態；考不考得到由 `canTake` 推出來另外顯示 | `canTake` 規定公開考卷不看審稿狀態，圖示寫死「考不到」就會錯。**不改 `canTake`、`permission.ts`**（那是授權規則） |

## 內容

### AC-5：狀態圖示說明和實際一致（含 AC-19）

- `examSet.statusTag.TP／TR／WAIT` 兩種語言都拿掉「考得到／考不到」，只講審稿狀態。
- 考不考得到：domain 加 `studentsCanTake(set)`（`statusTags.ts`），就是 `canTake(["student"], set)`，不另寫規則。題組列表的「開放對象」欄、審稿頁標題下方，顯示「學生考得到」或「學生考不到」。
- `examSet.accessHint.members` 補「審稿通過後」。
- 全專案搜尋「考不到」「can't be taken」，翻譯檔以外沒有別處。

### AC-1／AC-2：考卷列表的標題

- 頁首 `examList.title` 改成不帶 Section 的通用標題（「雅思聽力考卷」）。
- `AvailableExam` 加 `sections: { section, title }[]`，由 domain 純函式 `sectionTitlesOf(paper)`（`fullExam.ts`）從題目卷推，附測試。2.x 單段卷是空陣列。
- 列表：完整考卷顯示「完整考卷（4 段・40 題）」，下一行列四段的標題（例如「S1 Hotel booking・S2 …」），三套就看得出不一樣；單段卷照舊顯示題數，並標「Section 1」。
- 不改資料、不改資料庫。

### AC-3：完整考卷的代號

- 不改 setId（見決定紀錄）。共用小元件 `FullExamBadge` 在老師／管理員看得到 setId 的地方（題組列表、審稿頁）旁邊顯示「完整考卷」。

### AC-4：AI 意見的位置編號（含 AC-15）

- `splitTimeRefs(text, turnStarts, section)`：
  - PATTERN 直接認 `s\d+-t\d+`（以前 `s1-t10` 會被切成 `s1-` 和 `t10`）。
  - 只寫 `t10` 的，有 section 時先查 `s{n}-t10`，顯示成 `s{n}-t10 [mm:ss]`，和逐字稿同一種寫法。
  - 整套的意見（沒有 section）在完整考卷裡查不到就當一般文字，不亂猜。
- 點了：錄音跳過去，逐字稿那句捲進畫面中間、亮起來（只有從意見點才捲）。

### AC-6／AC-8：進度、送出、下一個待處理（含 AC-16）

- 進度（OK n・有問題 n・m 項待處理）和「送出審核」搬進現有的 sticky 錄音列，捲到哪都看得到。送出後的錯誤／已儲存訊息也放在錄音列裡。
- 「下一個待處理」按鈕寫明要去哪一項（「下一個待處理：第 3 題」／「整套」），按了展開那張卡、捲過去、亮起來一下。
- 全部判完：按鈕換成「沒有待處理了」字樣（不能按），旁邊顯示合格／不合格。
- 總評（comment）留在頁面底部。

### AC-7：逐字稿

- 拿掉 `max-h-96`，改 `max-h-[70vh]`。
- 完整考卷依 `s{n}-` 分段，每段一個小標「Section n」。
- 播放中不自動捲；只有從意見點過去才捲。

### AC-9：連接線

- 寬螢幕只畫展開中那張卡的線；其他卡不畫線。點空格或點卡照樣展開、看得到對應。

### AC-10：考試中看得出在第幾段

- `examTiming.sectionOf(events, t)`：從事件 id `^s(\d+)-` 推目前是哪一段；事件之間的空檔沿用上一段。狀態列前加「Section n・」。2.x 單段卷不顯示。

### AC-11：開始前的長度、題數、試音量（含 AC-17）

- intro 加「約 N 分鐘・M 題・K 段」。
- 試音量用 `public/landing-demo/audio.mp3`（不用考卷錄音，不吃取音檔次數上限），按鈕寫「試聽音量（不是考試）」，不計時、不開始考試。

### AC-12：配對題

- 下拉選單移到題號後面、題目前面（手機整行寬），選項顯示「A — 內容」；值仍是字母，草稿、批改不受影響。

### 共通（AC-13／14）

- 390px 不能整頁橫捲；#285 的離開提醒、交卷確認、草稿、標為已處理不能壞。實機用 3101 檢查。
- 新文字兩種語言 key 一致（`messages.test.ts` 會擋）。

## 實作時補的細節

- 考試頁開始後，說明和作答區用不同的 `key`：瀏覽器翻譯外掛改過 DOM 時，說明文字會被沿用成狀態列（實機看到），換 key 讓整塊重畫。
- 碰到的檔案寫死的顏色改 token：`StatusTags` 的老師通過（sky → accent）、`FullExamPaper` 的看題標黃（yellow → primary-soft）。`ExamPaper` 沒碰，不改。
- 老師總覽（`GetTeacherDashboard`）的待審清單多帶 `fullExam`，代號旁才能標「完整考卷」。

## 已知限制

- 整套的 AI 意見（不屬於某一題）在完整考卷裡寫 `t3`、`t19-20` 時，不知道是哪一段，維持一般文字不連結。產生端改成直接寫 `s3-t3` 才能根治（另開 Question.Generator 工作項）。
- `t19-20` 這種範圍寫法只認得前半（`t19`），沿用原本的規則。

## 不做

- 第 4 順位、#285 留下的事（見 issue）。
- 不改 setId、不改資料庫、不改 Question.Generator、不改 `canTake`／`permission.ts`。
