# 虛擬配音員（Voice Cast）計劃

狀態：**暫存計劃**。等 M4（錄音）、M5 完成後再回來補。2026-10-16 起草。

## 1. 為什麼要做

M4 試作（gym-0002，Kokoro）遇到的問題：

- Kokoro 逐字母拼字不穩：A 常被吞掉、字母擠在一起，沒有重音／音量控制。
- 試過字母名稱字、音標、逐字母合成、各種標點分隔、Piper 換引擎，都沒有穩定解法。
- 網路上也沒有「開源本地模型穩定拼字」的現成做法；商用引擎靠 SSML 的 say-as characters。
- Kokoro 沒有澳洲、加拿大口音。

想法：先準備幾個固定的「虛擬配音員」，國籍、性別、年齡各不同；A–Z、0–9 等固定片段由每位配音員預錄一次、驗證一次，之後所有題目重複使用。

## 2. 設計

### 2.1 配音員資料（每人一筆）

| 欄位 | 說明 |
|---|---|
| id | 例如 us-f-1 |
| 口音／國籍 | us、uk、au、ca… |
| 性別、年齡層 | 供角色指派（學生用年輕聲音、櫃檯用成人聲音） |
| 引擎與聲音 | 引擎名稱＋聲音 id 或參考錄音檔 |
| 預錄庫路徑 | 字母、數字、常用詞 |
| 授權說明 | 聲音來源、可否商用、參考錄音的授權 |

### 2.2 預錄庫內容（每位配音員）

- A–Z 字母名稱（含重音、較慢、較大聲，字母間距由程式固定 0.25 秒）
- 0–9、oh、double、triple（電話、房號、編號用）
- 常用短語待定（例如「Could you spell that?」）
- 旁白固定句（Section 1 播報詞）屬於「旁白配音員」，已在 M4 設計中

### 2.3 使用方式

- 題目生成時，對話的 A、B 角色各指派一位配音員，旁白指派一位。
- 一般句子照 M4 流程逐句合成。
- 拼字句：名字念完停 0.6 秒，再由說話者的字母庫接出字母，拼完停 0.4 秒再接後面的話。
- 數字串：逐位接預錄庫。

### 2.4 預錄庫的來源（三條路，待選）

1. **Kokoro 生成＋人工挑選**：每個字母生成 3–5 個版本，人聽一次選最好的。成本最低，無授權問題；每個新配音員都要重做。
2. **聲音複製模型**（Chatterbox、Qwen3-TTS，Mac 上可用 mlx-audio）：用參考錄音複製聲音，可補澳洲、加拿大口音。要先確認參考錄音授權（Common Voice 禁止辨識說話者，不適合）。
3. **商用引擎的固定聲音**：品質最好、原生支援逐字母；有費用，授權看條款。

初步傾向：先走 1，澳加口音再評估 2。

## 3. 初步選角（先 4 位）

美女、美男、英女、英男，對應 Kokoro 現有聲音（測試中：旁白 bm_george、A am_michael、B bf_emma）。澳洲、加拿大待補。

## 4. 待辦（M4、M5 之後）

1. 決定配音員人數與預錄庫來源。
2. 做「字母挑選」小工具：每字母多版本，人聽後點選，存成字母庫。
3. `make_audio` 改成讀配音員資料表與預錄庫，取代現在的 `regap` 切割做法。
4. 驗證：用 ASR 做粗篩，最終由人聽（ASR 聽不出口音與重音）。
5. 補澳洲、加拿大口音。
6. 在 spec 加一節，並更新 timing.json 的拼字事件。

## 6. 相關事實（調研摘要）

- Kokoro：無 SSML、無重音控制，停頓只靠標點。
- Piper 四個聲音單獨念字母，ASR 辨識正確 4–19／26，沒有比 Kokoro 好。
- mlx-audio 支援 Kokoro、Qwen3-TTS、Chatterbox、Dia、CSM 等；各模型頁面皆未列拼字控制。
- Qwen3-TTS：Apache-2.0，Mac 支援有限（截至 2026 年初）。
