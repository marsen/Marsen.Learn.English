### 建議

- [ ] `src/presentation/lib/audioStatus.ts:14`、`src/presentation/components/admin/ReviewForm.tsx:365`：把 `networkState === NETWORK_NO_SOURCE` 也算成「讀不到」，可能誤報。HTML 規格的資源選擇第一步會先把 `networkState` 設成 `NETWORK_NO_SOURCE`，等到 stable state 才改成 `NETWORK_LOADING`。如果 effect 在同一個 task 裡就跑了（例如同步更新後馬上 flush），會先閃一下「錄音讀不到」，等 `loadedmetadata` 才消失。用 `src` 屬性載入失敗時（404、格式不支援），規格本來就會設 `error`（`MEDIA_ERR_SRC_NOT_SUPPORTED`），所以只看 `el.error !== null` 就夠了。如果要保留 `networkState`，可以再加上 `el.readyState === 0` 和 `el.error !== null` 一起判斷。測試「找不到能播的來源時算讀不到」也要跟著改。目前頁面是伺服器端產生、用 transition 導頁，實際發生的機率低，所以列為建議。

### 可選

- [ ] 文字「請聯絡管理員重新上傳」：如果是管理員自己在審，會叫他去找自己。可以改成「這份的錄音讀不到，需要重新上傳。」，誰看都通。
- [ ] 播到一半網路斷掉（`MEDIA_ERR_NETWORK`）也會顯示「讀不到」，而且要重新載入或成功載入 metadata 才會消失。現在的行為可以接受，記下來就好。
- [ ] 沒做人工畫面確認（錄音 404 時提示的位置在黏住的錄音列裡）；合併前建議在本機把 `AUDIO_LOCAL_DIR` 裡的檔案改名，看一次。
