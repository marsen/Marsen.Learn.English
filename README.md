# Marsen.Learn.English

兩個靜態候補頁，用來測「有沒有陌生人願意留 email」：

- `/listening/`：雅思聽力練習（仿格式、無限新題、錯題類型分析）
- `/fluency/`：英文流利度練習（對照組）

兩頁共用同一份版型、樣式和腳本，只差在題材。`npm run check` 會強制兩頁的區塊結構一致，
這樣測出來的轉換率差異才能歸因於題材，而不是版面。

## 本機跑起來

```bash
npm install        # 只有跑測試需要（jsdom）；頁面本身沒有任何相依套件
npm run dev        # 開 http://127.0.0.1:5173/listening/?src=local
npm test           # 23 個測試：載入頁面、填表送出、錯誤處理、檢查腳本
```

`?src=` 後面接來源名稱，這個值會跟著表單一起記下來。

## 檢視題組（review/）

開發者自己用的本機頁面，把 Question.Generator 打包出的 `set.json` 變成看得懂的報表：審稿結論、示警與 AI 裁決、每題答案與陷阱、錄音時間軸（可播放、點一下跳段）、題目卷（可切換顯示答案）、製作紀錄。

```bash
npm run dev     # 然後開 http://127.0.0.1:5173/review/
```

把題組資料夾拖進頁面：一套的資料夾，或 Question.Generator 的 `results/out`（裡面很多套，會先出一張總表，點一列看細節）。每套的 `audio.mp3` 會核對雜湊。也可以用「選檔案」單選 `set.json`。檔案只在瀏覽器裡讀，不上傳。**set.json 含標準答案，所以 `review/` 不在 `scripts/build-public.mjs` 的清單裡，不會部署上線**（有測試守著）。

## 要你填的東西

文案我沒有代寫。每個待填的位置都是一個黃色虛線框，裡面是該區塊要回答的問題。
直接把整個 `<h1 data-todo>…</h1>` 的內容換成你的話，並把 `data-todo` 屬性刪掉。

```bash
npm run check      # 列出還有哪些沒填、設定缺什麼；有任何錯誤就以非 0 結束
```

沒有「已填完」的假象：只要還有 `data-todo`，頁面左下角就會有一條黑色提示列，`check` 也會擋下。

## 設定（assets/config.js）

| 欄位 | 說明 |
|---|---|
| `formEndpoint` | 表單接收端網址。留空 = 本機測試模式，資料只存在瀏覽器的 localStorage |
| `formMode` | `"cors"`（會回應 JSON 的服務，例如 Formspree）或 `"no-cors"`（Google Forms） |
| `fieldMap` | 欄位改名對照。Google Forms 要把 `email` 對應成 `entry.123…` |
| `contactEmail` | 頁面上「要求刪除資料」的信箱。上線前必填 |

**用 Google Forms 的話**：建一份有 email、考試時間、頁面、來源等短答欄位的表單，取得「預先填入的連結」就能看到每個欄位的
`entry.` 編號；把網址尾端的 `/viewform` 換成 `/formResponse` 當 `formEndpoint`，`formMode` 設為 `"no-cors"`。
`no-cors` 看不到對方的回應，所以上線後請自己送一筆，並到後台確認真的收到。

## 統計與轉換率

把統計服務（Plausible、Umami、Cloudflare Web Analytics 擇一）的 script 貼在兩個頁面 `<head>` 的註解下面。
沒有它，`check` 不會放行，因為沒有造訪數就算不出轉換率。

頁面會送出這些事件（有統計服務就一併送出，沒有的話只記在瀏覽器的 `window.__events`）：

| 事件 | 時機 |
|---|---|
| `cta_click` | 按首屏的「加入候補名單」 |
| `form_start` | 第一次點進表單 |
| `form_invalid` | email 格式不對 |
| `form_submit_success` | 成功送出（帶 `page`、`src`） |
| `form_submit_failure` | 送出失敗 |

轉換率 = `form_submit_success` ÷ 該頁該來源的造訪數。議會的停損條件用的是這個數字（低於 1% 要處理）。

## 來源連結

發文時每個管道用不同的 `src`，才知道人是從哪裡來的：

```
https://你的網域/listening/?src=ptt
https://你的網域/listening/?src=dcard
https://你的網域/fluency/?src=ptt
```

同一個工作階段內，重新整理或從別頁回來，來源會沿用第一次記下的值。

## 上線前

1. 補完文案、設定 `config.js`、貼統計 script。
2. `npm run check` 全部通過。
3. 自己用真實網址送一筆，確認資料真的進了後台。
4. 發文前先讀各版的版規；用「我在做這個工具，想請教」的口吻，並說明這是你的專案。

**託管**：這是純靜態檔案，任何靜態託管都能放。Vercel 的免費方案限定非商業的個人用途，為了賣東西而做的頁面
是否算商業用途請先看它的條款；其他託管商的免費方案條款我沒有逐一核對，上線前請自己確認。

頁面預設有 `noindex`（不讓搜尋引擎收錄），測試期間這是合理的。

## 頁面上的固定文字（我寫的，你可以改，但要自己負責）

- 「目前是候補名單。產品還在準備中，現在不收款。」：只要頁面上沒有付款功能，這句就是事實。
- 「你的 email 只用來通知開放，可以隨時寄信到 … 要求刪除。」：**這是承諾**，有人來信就要真的刪。
- 聽力頁的免責聲明與頁尾：與 IELTS 官方無關、不代表正式分數。措辭我不是律師，上線前請自己再確認。

`check` 會擋下「保證」「必過」「官方授權」這類字眼，以及缺少上述三段文字的頁面。

## 刻意沒做的事

- 沒有付款、沒有帳號、沒有後端。資料只放在你選的表單服務裡，不在這個 repo。
- 沒有範例題目與音檔。第一版先量興趣；如果造訪不少但轉換偏低，再補一份範例 Section。
- 沒有 A/B 價格。兩頁只差題材，價格反應改在訪談時問。

## 已知限制

- 版面還沒有在真實瀏覽器裡看過：測試只涵蓋行為（載入、送出、錯誤、檢查），沒有涵蓋視覺。
  請用手機和電腦各開一次，看到哪裡怪就告訴我。
- 字型用系統字型（macOS 的蘋方、Windows 的微軟正黑體），沒有載入外部字型。
- 本機測試模式的資料存在瀏覽器裡，清掉網站資料就沒了。
